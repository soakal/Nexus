  fixed; the NFS switch only stops it from being visible.** Since 2026-10-01 the Proxmox kernel has
  logged **2,675** `nfs: server 192.168.1.50 not responding, still trying` messages, with 1,455
  matching recoveries, clustered exactly in the backup windows (230 during the 11:00 manual VM 102
  run, then 190 / 423 / 20 / 357 across 22:00–01:00 on the nightly). So Unraid still stalls

  `Proxmox.md`'s diagnosis correctly named the mechanism (a `soft` mount returning I/O errors when
  the SMB server is slow) but attributed it to the CIFS plugin's hardcoded flag rather than to the
  server, which is why the "fix" didn't hold.
