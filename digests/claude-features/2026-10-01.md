## 2. "Plan mode is dead" — why interactive planning is replacing it, and how plan mode actually works under the hood [New technique]
A Sept 24 essay by ex-GitHub engineer Ayman Nadeem hit HN's front page (538 points, 469 comments) arguing that upfront, approved specs still produce subtly wrong code — and a Claude Code team member replying in the thread confirmed a genuinely non-obvious implementation detail: plan mode in Claude Code has never changed the toolset available to the model, only added a prompt-level reminder ("you're in plan mode, don't code yet") — because swapping tools between modes would break prompt caching. As models follow instructions better, teams are shifting from "approve a plan upfront" toward conversational, iterative planning instead of a hard gate. Confirmed via the HN thread itself plus a reply from a Claude Code team member in it, high confidence.
Tie-in: relevant to how Brian structures Council Loop's Arbiter-plans/Engineer-implements split and any skill/subagent design that leans on plan-mode as a safety gate — the actual mechanism (prompt nudge, not a tool-restriction) is worth knowing when deciding whether a formal plan-approval step is pulling its weight versus just talking through the plan conversationally first.
