# Claude + AI Digest — 2026-11-14

**1. [New capability] Claude Code jumped straight to 2.1.325 (skipping 2.1.324), and the big one for anything unattended: scheduled tasks and `/loop` now ask before running a skill that declares `allowed-tools` or hooks.** You now need `Skill(name)` added to `permissions.allow` to keep that skill running without a prompt. The same release also defaults sandboxed Bash commands back to the normal permission flow (`sandbox.autoAllowBashIfSandboxed: true` restores no-prompt behavior), plus several real permission-bypass fixes: a Bash allow rule that could run a different program than the one it names, a gap where some compound commands ran without asking, and relative deny/ask rules (e.g. `Read(./.env)`) that stopped covering the project after a `cd` now also apply in added directories. Source: official `CHANGELOG.md` on `anthropics/claude-code`, paraphrased not quoted — no date field in the file itself, and it's a large batch (100+ line items), so treat the above as the highlights, not the full list.
Tie-in: **Council Loop** drives itself unattended via `/loop` with auto-commit on acceptance — exactly the pattern this change targets. If Council Loop's skill (or any hooks it relies on) declares `allowed-tools`/hooks, it may now stall on a permission prompt nobody's watching, rather than running through; worth adding the right `Skill(name)` entry to `permissions.allow` before the next unattended run, and double-checking whether its Bash calls are sandboxed and need the `autoAllowBashIfSandboxed` setting too.
