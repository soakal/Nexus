# Claude + AI Digest — 2026-10-15

## 1. Permission/hook input validation hardened, plus a dead sandbox-flag cleanup [New capability — priority watch-list]
Claude Code 2.1.300 (official GitHub `CHANGELOG.md`, high confidence) now validates `updatedInput` returned by `PreToolUse`/`PermissionRequest` hooks the same way Claude's own tool input is validated: unknown keys are silently dropped, and input the target tool itself would reject now denies the call outright, rather than letting a hook hand back malformed input that slips past the normal checks. Separately, `--sandbox`/`--no-sandbox` were removed from `claude remote-control` — they had no effect there and now error instead of silently no-opping; `sandbox.enabled` in settings is the real switch.
No specific tie-in — this is a general permission-surface hardening fix worth knowing about, not tied to a particular repo's config.

## 2. MCP reconnect-after-compaction and bad-schema bugs fixed [New capability — priority watch-list]
Also 2.1.300: three MCP robustness fixes. Claude no longer stays blind to an MCP server's tools/instructions until its next tool call when that server finishes reconnecting after a compaction; a tool whose input schema the API rejects no longer breaks every subsequent turn with a 400 (Claude Code now resends it with no parameters for the rest of the conversation instead of repeating the failure); and automatic tool search (`ENABLE_TOOL_SEARCH=auto`) no longer silently turns off mid-conversation while MCP servers reconnect after a resume.
Tie-in: directly relevant to MCP_Obsidian and the Chrome browser-automation MCP server — both are long-lived custom servers that can legitimately reconnect mid-session (after a compaction or a resumed session), which is exactly the scenario these three fixes target.

## 3. Resuming a headless/Agent SDK session after compaction no longer loses recent history [New capability]
Same release: two related fixes ensure that resuming a headless or Agent SDK session correctly keeps the most recent messages (not just the compaction summary) when the compaction followed a reply that was cut at the output-token limit, or followed a retried/unfinished reply in the same turn — previously such a resume could silently drop recent context or bring back pre-compaction history.
Tie-in: relevant to Council Loop's unattended `/loop` driver sessions and to this digest routine itself, both of which run as scheduled/headless-style sessions that can span a compaction — no action needed, this is a transparent correctness fix.
