# Claude + AI Digest — 2026-11-17

**1. [New capability] Claude Code 2.1.326 ships a batch of permission/sandbox/Bash fixes.** This is the newest version in the official GitHub CHANGELOG.md, up from 2.1.325 (known as of yesterday's digest). Fixed this release: a misleading "Dangerous rm operation" warning firing on some commands with no `rm` at all; `cp` of a file being wrongly refused when only its *source* path was covered by an `Edit` deny rule; and some tool calls in bypass-permissions mode now ask for approval or are refused outright rather than running unchecked. Also tightened: Bash permission checks and Code Mode's sandboxed-command checks both now ask/refuse more often, sandboxed commands on macOS/Linux/WSL no longer write to some sensitive home folders by default, and `claude mcp serve` now ignores `sandbox.excludedCommands`. Source: official CHANGELOG.md, paraphrased not quoted; no date header on the entry, but it's new since the 2026-11-16 digest's 2.1.325 baseline.
Tie-in: **Council Loop** runs unattended with auto-commit on acceptance and nobody watching the terminal — the same unattended-bypass class this release keeps tightening (misjudged deny rules, under-checked bypass-mode calls). Worth confirming the loop's Claude Code install is actually on 2.1.326 before another long unattended run.

**2. [New capability] Same release fixes `/mcp` not showing why a local (stdio) MCP server failed to start, plus a tool-search bug that could load the wrong MCP server's tool when asked for one by exact name.** Also fixed: MCP prompts disappearing when two servers have near-identical names, and a stale reconnect to an MCP server an SDK host had just removed. Source: official CHANGELOG.md.
Tie-in: **MCP_Obsidian** (and NEXUS's own `:8765` Brain MCP server that `brain_organizer` talks to) are exactly the kind of local/stdio-adjacent custom servers that used to fail silently — the `/mcp` fix gives a real error surface instead of a guessing game next time one of them won't start.
