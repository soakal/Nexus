## 1. Claude Code v2.1.267: `maxEffortLevel` org-wide effort cap + fresh-render system prompt flag [New capability]
Confirmed via the raw GitHub changelog (primary source) and cross-checked against two independent changelog trackers (claudeupdates.dev, ai-tldr.dev) — high confidence, genuinely new since the 09-09 digest's v2.1.266 coverage. Two notable additions: a `maxEffortLevel` setting (top-level or per-model under `modelSettings`) that caps the highest effort level anyone on a team/org can select, enforced across Bedrock/Vertex/Foundry regardless of provider; and a `--system-prompt-snapshot off` flag that re-renders the system prompt fresh on every request instead of reusing the one recorded at session start, useful when iterating on prompt text and wanting changes to take effect immediately. Also in this release: several prompt-cache fixes for tool definitions/MCP servers, `/diff` panel and VSCode extension fixes, and better Bash tool/sandbox guidance text. Tie-in: `maxEffortLevel` is really an org-governance knob (not obviously useful solo), but the snapshot flag is a direct fit for skill/CLAUDE.md authoring work (ponytail mode, project skills, this digest's own instructions file) — it removes the "restart the session to see your prompt edit take effect" friction while iterating on system-prompt-shaped text.

## 2. Claude Code's native LSP tool: go-to-definition/find-references/live diagnostics instead of grep [New technique]
Moderate confidence, search-snippet level (the CircleCI writeup and a José Valim technical critique on X were the two best sources found, but both were blocked by this session's egress proxy before they could be fetched in full — reporting only what search snippets/summaries confirmed). Claude Code has shipped an LSP (Language Server Protocol) tool since v2.0.74 — it needs a language server configured for the project (either manually or via a marketplace plugin), and once wired up gives Claude real code intelligence (jump-to-definition, find-all-references, hover docs, live diagnostics as it edits) instead of inferring structure from grep/read. One noted rough edge: most LSP APIs want `file:line:column` addressing, which is awkward for an agent that thinks in symbol names ("where is Foo#bar defined") rather than coordinates — so the win is real but not frictionless. Tie-in: worth trying on NEXUS's own backend (a large-ish Python/FastAPI codebase) or any of Brian's bigger repos where Claude currently re-discovers call sites via Grep each session — an LSP-backed session could navigate more precisely on first pass instead of re-deriving structure via search.
