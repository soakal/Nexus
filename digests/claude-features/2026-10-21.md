## 1. Claude Code's `stable` channel has fallen behind again — `latest`/`next` jumped to 2.1.306 while `stable` sits at 2.1.304, and the new release adds a sandbox setting the changelog itself calls a possible bypass [New capability]
Checked directly against the npm registry (high confidence): as of 2026-10-21, `stable` is still pinned at 2.1.304 (released Oct 19) while `latest`/`next` moved to 2.1.306 (Oct 21) — reopening the gap that closed in yesterday's digest. 2.1.305 (Oct 20) added `sandbox.allowNestedUserNamespaces`, a new setting that lets sandboxed Linux commands create user namespaces; the official changelog states plainly that enabling it "can also bypass the sandbox's file protections." The same release fixed a regression from 2.1.304 where tool-search requests were outright rejected by some providers/gateways (now retries without tool search instead of failing), plus smaller fixes to `/effort`/`/autocompact`, worktree base-branch handling, and MCP server overrides. 2.1.306 (Oct 21) fixed `claude -p` wrongly reporting "not logged in" in cloud sessions started without the session's env vars, and fixed API errors being mislabeled as "prompt is too long" (with unneeded compaction) in sessions using many MCP tools.
Tie-in: worth confirming `sandbox.allowNestedUserNamespaces` stays off wherever Claude Code touches NEXUS code on Linux (devbox, nexus-lxc) — NEXUS's own safety model is built around the broker (`backend/safety/broker.py`) being the one deliberate chokepoint that can bypass normal write constraints, so a sandbox setting explicitly documented as a potential file-protection bypass deserves the same wariness as any other privilege-escalation path, not a casual opt-in for convenience.
