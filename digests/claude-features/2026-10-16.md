## 1. Workflow tool: two real reliability fixes land in 2.1.301 [New capability]
Claude Code 2.1.301 (official `CHANGELOG.md` on GitHub, high confidence) fixes two bugs in workflow-agent execution: a workflow agent could silently skip its assigned step while the run still reported success, and a workflow script could be asked for permission again (or refused outright) on every read/edit/re-run after a `Bash cd` earlier in the same session. Both are plain correctness fixes to the machinery behind the Workflow tool, not new functionality.
No specific repo tie-in — this is about the Workflow tool itself, which you already use for pipeline/parallel multi-agent orchestration across projects, not any one project's config.

## 2. Grep/Glob now report a real search failure instead of a false "no matches" [New capability]
Also 2.1.301: previously, if the underlying search program (ripgrep/glob) failed unexpectedly before returning any results, Claude Code reported a clean "no matches" — indistinguishable from a genuinely empty result. It now returns an explicit "search failed" error instead.
Worth knowing for any large-repo session (NEXUS's own `backend/`/`frontend/` tree included) where that silent empty-result false negative could previously have been mistaken for "nothing there" rather than a tool crash.

## 3. Two more permission/hook-surface hardening fixes [New capability — priority watch-list]
Same release: an artifact update that a `PreToolUse` hook covering Edit or Write used to refuse outright now succeeds — Claude edits the file first, then republishes, instead of trying to change it inline in the publish call. Separately, quitting Claude Code no longer silently removes a worktree a `WorktreeCreate` hook made, without asking, when that worktree might still hold unpushed commits.
Tie-in: the worktree-quit fix is relevant given how much NEXUS work happens in a fresh git worktree per feature (`nexus-pulse`, `nexus-dashboard-cache`, etc., per this repo's own CLAUDE.md) — if any of those are ever created via a mod's `WorktreeCreate` hook rather than by hand, this closes a real "lost work on quit" gap.
