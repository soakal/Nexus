## 1. Claude Code v2.1.282: prose-width control, telemetry visibility, Chrome+managed-MCP coexistence, and reliability fixes [New capability]
Released since yesterday's digest (which covered 2.1.281). Adds `maxProseWidth` to cap prose width in wide terminals while keeping tables/code full-width, a startup notice plus `/status`/`claude doctor` entries listing which telemetry settings got ignored or disabled, and `allowClaudeInChromeWithManagedMcp` so `claude --chrome` can run alongside an exclusive `managed-mcp.json`. Bug fixes: 400 errors in conversations holding undecryptable web-search results from third-party gateways, resumed sessions re-sending earlier turns in altered form (losing prior reasoning), and extended thinking getting dropped when a slash command ran mid-turn. Confirmed via the official GitHub CHANGELOG.md, cross-checked against a same-day third-party release tracker (high confidence).
Tie-in: `allowClaudeInChromeWithManagedMcp` is directly relevant to your existing Chrome-automation MCP server setup — if you ever pin an exclusive `managed-mcp.json`, this is the setting that stops it from locking `--chrome` out.

Real reach (original X post plus multiple independent secondary write-ups) but exact view/engagement numbers weren't independently confirmable from here — treat the "went viral" framing as reasonably well-corroborated, not verified at the numbers level.
Tie-in: a live example of exactly the oversight gap NEXUS's broker/confirm-gate design and Council-loop's role-split exist to prevent — worth noting as external validation of that architecture choice, no action needed.
