## 1. Claude Code 2.1.307/2.1.308 ship — `stable` catches back up, plus a new safety-event telemetry stream and a real MCP double-fire fix [New capability]
Checked directly against the npm registry and the official CHANGELOG.md (high confidence): `stable`/`latest`/`next` are now all 2.1.308 (released 2026-10-22, bug fixes only) — the `stable`-lagging-`latest` gap flagged in yesterday's digest has closed again. The preceding 2.1.307 (2026-10-21) adds a new `claude_code.safety_event` OpenTelemetry event that fires for every tool call a permission rule, auto mode, a safety check, a hook, or the sandbox stopped, prompted, or sent back — a new audit signal for exactly the kind of gating NEXUS's own broker does. The same release fixes a real correctness bug: HTTP MCP tool calls being sent twice when the connection closed mid-call (now only read-only/idempotent tools are retried), plus MCP servers wrongly reporting "needs authentication" when the macOS keychain was locked, and connections wrongly marked timed-out after the machine slept.
Tie-in: the MCP double-fire fix is directly relevant to **MCP_Obsidian** — if Claude Code itself is ever the client talking to that vault-tools MCP server (or to NEXUS's own Brain Organizer MCP server at `:8765`), a dropped connection used to risk a non-idempotent tool call firing twice; 2.1.307 closes that specific gap. The new `safety_event` telemetry is also a reasonable model for NEXUS's own `ActionLog`/`OutcomeFlag` audit trail if Brian ever wants a comparable "what almost got blocked" stream in Claude Code itself.

Given the vague "breaking changes" entry, worth reading the real migration notes (not just the changelog line) before ever bumping NEXUS's pin past 1.x, the same caution this file already applies to the `mcp`/`starlette` pin.
