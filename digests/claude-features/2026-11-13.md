# Claude + AI Digest — 2026-11-13

**1. [New capability] Claude Code 2.1.323 closes a batch of real permission/sandbox bypasses.** This is the newest version in the official GitHub CHANGELOG.md, up from 2.1.322 (known as of yesterday's digest, which only added Vertex fast mode). Fixed this release: Bash deny/ask rules missing commands run through `sudo`/`env`/similar wrappers and commands written with combined `sudo` flags; a dangerous `rm` could be judged from the wrong folder and skip its removal-confirmation prompt under bypass permissions or an allow rule; the Bash sandbox could silently switch off mid-session; and the sandbox's write-access grants could be walked past via a symlink pointing outside the granted folder. Also: `--permission-mode auto`/`defaultMode: auto` now always starts in ask-first Manual mode rather than a more-permissive one when auto mode isn't actually available on that host, and `claude -p`/the Agent SDK now refuse to start (instead of silently running Bash unsandboxed) when `--settings` turns the sandbox on but fails validation. Source: official CHANGELOG.md, paraphrased not quoted.
Tie-in: **Council Loop** auto-commits unattended on Engineer/Realist acceptance with nobody watching the terminal — exactly the unattended-bypass class this release targets (wrapper commands, wrong-folder `rm` checks, a sandbox that could switch off mid-run). Worth confirming the loop's own Claude Code install has actually picked up 2.1.323 before trusting it with another long unattended run.

**2. [New capability] Same release ships "Code Mode," an experimental opt-in where Claude writes JavaScript to call its tools instead of making native tool_use calls.** Toggle via code.claude.com/docs/en/code-mode; an org can also turn it off entirely. Source: official CHANGELOG.md.
Tie-in: conceptually close to what **NEXUS**'s own `router.run_with_tools` hand-rolls today — a multi-round loop where Claude calls read-only tools and the result is fed back round by round. Code Mode is Anthropic's own native version of batching/composing tool calls through written code rather than many round-trips; worth a look if NEXUS's tool-loop cost (each round is a separate billed call against the orchestrator's `claude-sonnet-5-5` executor) ever becomes worth optimizing.

**3. [New capability] Same release also fully removes the MCP v1 client from Claude Code (v2-only now, `MCP_SDK_GENERATION=v1` only gets a compatibility shim) and tightens project `.mcp.json` server approvals to match a server's exact declared name** — an approval saved under a different spelling of the same server now re-prompts. Source: official CHANGELOG.md.
Tie-in: Brian runs several custom MCP servers (the Obsidian vault server NEXUS's `brain_organizer` talks to on :8765, plus the separate **MCP_Obsidian** repo exposing vault tools to Claude generally) — worth a quick check that none of their declared server names have drifted, since this would now silently start re-asking for approval rather than erroring.
