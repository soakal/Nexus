**Hooks support five handler types, not just shell commands — plus a real conditional-matching layer** *(New technique, high confidence — verified directly against the official docs at code.claude.com/docs/en/hooks)*. Beyond the `command` type Brian already uses, hooks can be `http` (POST the event JSON to a webhook and act on the response), `mcp_tool` (call a tool on an already-connected MCP server), `prompt` (send the event to a fast model for a single-turn yes/no policy decision), or `agent` (spawn a subagent with Read/Grep/Glob to actually inspect files before deciding — e.g. "are these staged changes safe to commit"). Firing is also two-layered: a `matcher` (tool/event name or regex, e.g. `mcp__.*`) plus an optional `if` condition using permission-rule syntax (`Bash(rm *)`, `Edit(*.ts)`) that's more precise than parsing stdin JSON by hand. Tie-in: this is exactly the layer NEXUS's broker/confirm pattern and Council-loop's hooks live in — a `prompt`- or `agent`-type hook could do a cheap nuanced safety check (e.g. "does this touch `backend/safety/`?") before a destructive command runs, without writing a bespoke matcher script, and `if: "Bash(rm *)"` scoping is cleaner than the ad hoc Bash-parsing NEXUS's own `_client_source` sanitization work already had to reinvent by hand elsewhere.
