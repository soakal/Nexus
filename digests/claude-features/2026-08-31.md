## 2. Preview a Claude Code web branch live via GitHub Pages, with no Artifact CSP limits [New technique]
Simon Willison's TIL site (`til.simonwillison.net`, high confidence, corroborated by a Hacker News thread with the same title): when Claude Code for web builds a self-contained single HTML file (vanilla JS, CDN-loaded deps, no build step) on its own `claude/...` branch, pointing that repo's GitHub Pages settings at "Deploy from a branch" → that branch gives a live preview URL (`username.github.io/repo/index.html`) about a minute later. Unlike Claude's Artifacts, a page deployed this way has no CSP restrictions, so it can call JSON APIs on other domains directly. Tie-in: GLP APP is exactly this shape (a single-file HTML dose-calculator) — this is a way to get a real, shareable, API-call-capable preview URL for a Claude Code web session's output without provisioning any hosting yourself.

## 3. Subagents can get their own persistent, self-curated memory file [New technique]
Medium confidence — via a source-code deep-dive (buildingbetter.tech, the same article this digest partially mined on 2026-08-12 for other findings), corroborated by a GitHub issue thread. A subagent's frontmatter can set `memory: project` (or `user`/`local`, added v2.1.33) to get its own persistent directory (`.claude/agent-memory/<name>/` for project scope) — Claude Code auto-injects the first 200 lines of that subagent's `MEMORY.md` into its system prompt on every invocation and grants it Read/Write/Edit so it can update its own notes over time, effectively letting one named subagent accumulate expertise across separate runs instead of starting fresh each time. Caveat found in the same search: GitHub issue #57507 reports the auto-grant of Read/Write/Edit can get silently overridden if the subagent's frontmatter also sets an explicit `tools:` allowlist, leaving memory defined but non-functional — worth checking for that interaction before relying on it. Tie-in: this repo's own `security-reviewer` subagent (reviews changes to NEXUS's broker/safety surface) is a natural fit — a `memory: project` scope would let it remember past findings and confirmed-false-positives across review sessions instead of re-deriving them each time.
