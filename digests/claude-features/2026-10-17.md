# Claude + AI Digest — 2026-10-17

## 1. Fork subagents now default-on outside the terminal too [New capability]
Claude Code 2.1.302 (official `CHANGELOG.md` on GitHub, high confidence) turns on fork subagents (`subagent_type: "fork"`) by default in `claude -p`, the Agent SDK, the desktop app, and VS Code — previously only the terminal had them on by default (`CLAUDE_CODE_FORK_SUBAGENT=0` still opts out; `claude mcp serve` never offers them). Same release: the desktop app and VS Code now always run the main conversation's subagents in the background (matching the terminal) instead of letting Claude choose, while a subagent's own nested Agent calls default to foreground across `claude -p`/SDK/desktop/VS Code.
Tie-in: this is exactly the mechanism this digest routine itself runs on (an Agent-SDK-style scheduled session) and that Council Loop's Arbiter/Engineer/Realist roles lean on via the Agent tool — no action needed, but it means fork-subagent behavior is now consistent everywhere Brian runs Claude, not just the terminal.

## 2. MCP tool-schema negotiation bug fixed — servers could silently show zero tools [New capability — priority watch-list]
Also 2.1.302: an MCP server that negotiates the newer 2026-07-28 protocol version but omits `resultType`, `ttlMs`, or `cacheScope` in its response no longer gets treated as broken — previously that omission could make Claude Code see no tools from the server at all, or fail every call to it.
Tie-in: worth a one-time check against MCP_Obsidian's server if it was ever silently showing fewer tools than expected — this is precisely the omitted-field shape that would have triggered the old bug, and the fix is already live in 2.1.302.

## 3. Default permission mode changes for third-party-provider sessions with no mode set [New capability — priority watch-list]
Also 2.1.302: `claude -p` and Agent SDK sessions on third-party model providers that don't explicitly set a permission mode now start in `default` mode instead of `auto` (passing `--permission-mode auto` explicitly still works as before).
No specific NEXUS/Council-Loop tie-in — Brian's automation runs Claude Code sessions directly against Anthropic, not through a third-party provider, so this doesn't change behavior for him, but it's a real permission-surface default change worth knowing about per the priority watch-list.
