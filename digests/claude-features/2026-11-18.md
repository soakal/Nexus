**2. [New capability] Same 2.1.327 release adds a safer way to hand an MCP server its auth token.** `claude mcp add-json <name> -` now reads the server's JSON config from stdin instead of a command-line argument, so a bearer token never has to sit in shell history or a process listing. Also in this release: remote MCP servers reached by hostname over HTTPS get background retry for about a day instead of failing immediately, and MCP server logs now record only the mode/action/field-names of elicitation requests, not their content. Source: official `CHANGELOG.md`.
Tie-in: directly useful for **NEXUS**'s own `:8765` Brain MCP server and for **MCP_Obsidian** — both need a bearer token (`BRAIN_MCP_WRITE_TOKEN` for NEXUS) handed to a `claude mcp add` command; piping it via stdin next time either one gets reconfigured in a Claude Code session keeps it out of `.bash_history`.
