## 1. Claude Code 2.1.309 ships — permission/sandbox bypass fixes lead the release; `stable` still lags one version behind [New capability]
Confirmed directly against the npm registry's dist-tags (high confidence): `latest`/`next` are now 2.1.309 (published 2026-10-22 20:34 UTC), while `stable` sits one release back at 2.1.308 — the same stable-lagging-latest pattern flagged in yesterday's digest hasn't closed yet. 2.1.309's standout content is a cluster of real permission/sandbox-bypass fixes, not routine polish: a disabled MCP server could previously be silently reconnected by a later permission prompt; the Bash permission check could be fooled by a shell variable set from a command whose own redirect had actually failed; an `Edit(path)` deny rule could be routed around via a Bash redirect inside a subshell; and macOS `denyWrite` glob rules now resolve a path's real location when reached through a symlink (closing a classic symlink-bypass class of bug). A worktree-isolated session also now blocks some locale-prefixed and zsh arithmetic commands that its guard was supposed to catch already.
Tie-in: this is exactly the failure class **NEXUS**'s own `backend/safety/broker.py` gate exists to prevent (classify → decide → dispatch, backed by narrow validators like `_SAFE_CONTAINER_ID` and MAC-address normalization). The specific bug shapes here — trusting a variable set by a command whose redirect silently failed, a deny rule bypassed through a subshell redirect — are the same class of narrow-validator gap NEXUS has had to close in its own dispatchers before; worth a mental pass over broker.py's validators next time one gets touched.

## 2. `anthropic` Python SDK hits 2.2.0, and 2.0.0's vague "breaking change" turns out to be the sampling-parameter removal [New capability]
Confirmed via PyPI (2.2.0 published 2026-10-23, high confidence) and the SDK's own GitHub release notes: 2.2.0 adds API support for "message threads" and for usage/cost reports broken out by dimension (exact scope of "message threads" isn't detailed in the release notes themselves, so treat that part as a confirmed-but-thin lead), plus several Tool Runner (`client.beta.messages.tool_runner`) fixes — `set_messages_params()` callbacks were dropping or wrongly overriding `tools`/`betas`/`user_profile_id`/`workspace_id`, now fixed.
