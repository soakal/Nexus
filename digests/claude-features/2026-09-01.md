## 2. Scope a huge CLAUDE.md with per-directory files instead of one root file [New technique]
High confidence — official Claude Code docs (`code.claude.com/docs/en/large-codebases`). Instead of one root `CLAUDE.md` that grows to cover every subsystem (costing context on rules unrelated to the current task), Claude Code loads a per-directory `CLAUDE.md` on demand as it reads files there — a root file holds repo-wide rules, each subdirectory adds only its own conventions, and `/context` shows which files actually loaded. Companion settings: `claudeMdExcludes` to skip whole subtrees you never touch, and `worktree.sparsePaths` to check out only the directories a task needs when Claude creates a worktree (useful for subagent isolation). Tie-in: this repo's own `CLAUDE.md` is a single enormous root file spanning NEXUS's entire history — splitting it into a slim root file plus per-area files (e.g. one for the safety/broker layer, one for the Telegram/calendar integration history, one for the scheduler/durable-tasks machinery) would mean a session working on, say, the outcome tracker doesn't load the full Hermes-decommission or Proxmox-drilling history into context every time; `/doctor` can help trim what's already there first.
