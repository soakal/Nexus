## 1. Auto mode becomes the default permission mode in Claude Code, effective Aug 14 [New capability]
Confirmed via multiple corroborating sources (Simon Willison's writeup, an official Anthropic Claude account post, and independent coverage from MLQ/DigitalApplied) — high confidence. Starting August 14, new Claude Code sessions on Pro/Max/Team plans default to "auto mode" instead of prompting for every tool call: a classifier reviews each action and auto-allows safe ones while blocking anything irreversible, destructive, or reaching outside the working environment (usually finding a safer path or asking instead of just failing). Anthropic's own numbers: users approve 97% of prompts anyway, and in a 1,053-person test auto mode caught 89% of injected dangerous commands vs. 13.6% caught by humans manually approving. Opt out via Shift+Tab or `--permission-mode` (default/acceptEdits/plan); a managed-settings `disableAutoMode` flag exists for admins. Tie-in: this is close to a stock version of the exact pattern NEXUS's own action broker (`backend/safety/broker.py`) already implements by hand — classify risk, auto-allow low-risk, gate high-risk/irreversible on confirmation. Worth deciding deliberately whether to let a Claude Code session touching this repo run in auto mode once it lands, rather than it silently becoming the default on the next session.

## 3. Two lesser-known Claude Code authoring mechanics: skill `disable-model-invocation` and extra hook JSON fields [New technique]
Moderate confidence — surfaced via a source-code deep-dive (buildingbetter.tech, corroborated by independent hook-reference sites and Anthropic's own hooks docs page for the JSON-field claims); the original article itself was unreachable through the network egress filter, so this rests on secondary summaries, not a direct read. Two findings: (1) a skill's frontmatter can set `disable-model-invocation: true` to keep it registered but invisible to Claude's own auto-selection during intent matching — it only ever runs when a human types the skill name explicitly, useful for a skill that should never fire on its own; (2) beyond the well-known "exit code 2 blocks the action" hook contract, hooks can return JSON on stdout with `systemMessage` (surfaces a warning string to the user) and `terminalSequence` (desktop notification / window-title control) fields. Tie-in: Brian already authors custom skills and hooks — `disable-model-invocation` is a direct fit for any skill (e.g. something destructive-adjacent in the NEXUS or Council-loop toolset) that should require an explicit human invocation and never get auto-triggered by Claude's own judgment.
