# Claude + AI Digest — 2026-10-05

## 1. Claude Code 2.1.289 closes two more routes around Bash deny/ask rules, and `stable` is now 4 builds behind [New capability]
Two real sandbox bypasses fixed: a Bash deny/ask rule could be skipped when the dangerous part of a command sat behind an environment-variable prefix with an expanded value (e.g. `TZ="$HOME" rm -rf build`) under sandbox auto-allow, and separately when a bare variable assignment preceded the command. A third fix closes a `Read` deny-rule gap for files reached through a symlink. Confirmed directly from the official GitHub `CHANGELOG.md` (high confidence) plus a secondary write-up (mixed-news.com, via search summary) corroborating the release date — npm Oct 3 ~20:12 UTC — and that the `stable` tag was still pinned to 2.1.285 as of Oct 4 ~23:58 UTC, four versions behind `latest`/`next`.
Direct relevance: this session itself is running in Auto Mode, the exact context where a sandbox auto-allow bypass matters most — worth confirming `claude --version` is actually on 2.1.289+ rather than trusting `stable`, same wrinkle flagged in the Oct 3 digest and apparently still unresolved three days later.

## 2. Two model-lifecycle changes worth tracking — one already real, one just a date on the calendar [New capability]
Anthropic deprecated `claude-sonnet-4-5-20250929` on Sept 30, with a Nov 30, 2026 retirement date and `claude-sonnet-5-5` as the named replacement — confirmed on Anthropic's own official model-deprecations page (high confidence). Separately, that same page lists `claude-haiku-4-5-20251001` as still fully **Active** with no deprecation notice issued, but its tentative-retirement floor ("not sooner than October 15, 2026") is now 10 days out — a date worth having on the radar, not something requiring action yet.
Tie-in: NEXUS's `HAIKU_MODEL` constant and `_PRICE_PER_MTOK` table in `backend/agents/router.py` hardcode `claude-haiku-4-5-20251001` directly (it's the router/classify model for every chat turn) — Sonnet 4.5 was never pinned anywhere in this codebase so that half needs no change, but Oct 15 is the earliest Anthropic could start the clock on Haiku 4.5, so it's worth a glance back after that date rather than assuming "Active" means indefinitely so.

## 3. New-to-Brian technique: "Plan mode is dead" — plan mode was always just a prompt, not a toolset change [New technique]
An essay that spread through developer circles argues the discrete plan→approve→execute flow is being superseded by a continuous loop (understand, act, inspect, clarify, adjust) now that models follow instructions well enough not to need a guardrail mode. A Claude Code team member confirmed on the Hacker News thread that plan mode has never changed Claude Code's toolset — it only appends a reminder like "you're in plan mode, don't code yet" to each message — specifically because swapping tools mid-session would invalidate the prompt cache and cost real money. Found via Hacker News discussion (`news.ycombinator.com/item?id=49840054` and the team-member reply at `id=49850929`), medium-high confidence on the mechanism since it's a direct maintainer statement, not speculation.
Tie-in: worth knowing as a documented critique of Council Loop's own architecture (Arbiter plans, Engineer implements, Realist reviews) — not a reason to change it, but useful context that the discrete plan/execute split Council Loop hard-codes is the exact pattern Anthropic's own CLI is now also moving away from as a default mode.

## 4. DeepSeek ships V4.1-Flash — a 552B MoE model, but not actually runnable locally yet [Other AI]
DeepSeek released V4.1-Flash on Oct 4: a 552B-parameter Mixture-of-Experts model (8B active on prefill, 16B on decode) with a new causal encoder-decoder architecture, native multimodality, a 1M-token context window, and MIT-licensed weights published same-day. Confirmed via multiple model-tracking aggregators (llmgateway.io, llm-stats.com) referencing the release; benchmark/architecture claims are DeepSeek's own framing, not independently re-verified here.
Ollama status, checked directly: it's rolling out on Ollama's hosted **cloud** tier (Max/Team accounts first) — not a local pull. Community GGUF conversions exist on Hugging Face, but at Q2_K/Q3_K_M they run 264–323 GiB, and Ollama/llama.cpp's runtime reportedly can't yet load this architecture locally regardless of quantization (a compatibility gap, not just a size one). No realistic tie-in to SOPForge's Ollama fallback at this size — flagging for awareness only, not as something actually pullable today.
