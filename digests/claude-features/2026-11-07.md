## 1. Claude Code 2.1.319 — deny-instead-of-prompt setting, MCP task backgrounding, bash bypass fixes [New capability]
Found in the official changelog and GitHub releases page (high confidence, read directly), published Nov 6 — new since 2.1.318, covered in the 2026-11-04 digest. Three things stand out: a new `permissions.denyInsteadOfPrompting` setting turns a would-be interactive permission prompt into an outright denial instead of blocking; MCP tool calls in a terminal session are now backgrounded immediately with the result reported back when ready (`CLAUDE_CODE_DISABLE_MCP_TASKS=1` to opt out); and several Bash deny/ask-rule bypasses were closed, including `sed`-based evasions and env-var-prefix tricks, plus `which` with unusual flags now correctly asks first. Priority watch-list: the bypass fixes are exactly the permission-safety class this digest tracks, and the MCP change touches the protocol-adjacent surface Brian's stdio servers live on (though it's a client-side backgrounding behavior, not an `mcp` package/spec change — no new `mcp`/`starlette` release this window, NEXUS's pins are unaffected).
Tie-in: `denyInsteadOfPrompting` is a good fit for **Council Loop** specifically — its autonomous `/loop`-driven build cycle runs unattended, so a permission prompt it can't answer currently just stalls the loop; this setting would make an unapproved action fail fast and visibly instead. The MCP task-backgrounding change is relevant to Brian's own **MCP_Obsidian** server and his Chrome-automation MCP server — a slow vault or browser tool call in an interactive Claude Code session no longer blocks the terminal while it runs.
