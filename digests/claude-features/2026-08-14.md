## 1. Claude Code 2.1.232: subagent forking is now ON by default, plus cross-session @-mentions [New capability]
High confidence — confirmed via the raw GitHub CHANGELOG and corroborated by the Claude Code Changelog tracker on X and DevelopersIO's write-up. A `subagent_type: "fork"` subagent now inherits the full conversation history and prompt cache by default (previously opt-in), and non-teammate agent spawns in interactive sessions now run in the background by default. Separately, typing `@` in a prompt now lets you mention another live Claude session by name and reach it directly via SendMessage, with new `/config` rows to accept/hold/refuse inbound cross-session messages. Also in the same batch: GitLab support in plugin marketplaces, secret redaction for GitLab token families, and security fixes for a PowerShell parameter-injection bypass and a Windows Git Bash symlink exploit. This one's worth reading closely rather than skimming past — Brian already runs Agent-tool subagents and multi-session setups (this very session shows up in `ListAgents`), so the forking-default change alters the cost/context profile of subagent calls he's already making, and the @-mention feature is a lighter-weight alternative to manually looking up a session name via `ListAgents` before `SendMessage`.

## 3. Claude Code's `http` hook type can hold a synchronous approval gate open for up to 10 minutes [New technique]
Medium confidence — the 600-second default timeout for `command`/`http`/`mcp_tool` hooks (vs. 30s for `UserPromptSubmit`/`prompt` hooks) is confirmed straight from the official Claude Code hooks reference docs; the specific "route the approval to an external system before Claude proceeds" pattern (one write-up described wiring a PreToolUse hook to a physical approval button) came from a lower-confidence secondary source and couldn't be independently verified beyond the docs confirming the mechanism is technically sound. The idea: instead of a `command` hook that just runs a local script, an `http` hook POSTs the event as JSON and will wait up to 600s for the response — long enough to park a tool-call decision on a human (Slack approval, a physical button, anything with an HTTP endpoint) rather than only fire-and-forget scripting. Conceptually similar to NEXUS's own broker confirm-gate, but this is a way to get an external human-in-the-loop checkpoint directly at the Claude Code CLI level for local/ad-hoc automation, without building a broker for it.
