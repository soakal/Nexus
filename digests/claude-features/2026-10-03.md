## 1. Claude Code 2.1.288: fixes a dangerous `rm` safety check that a `bash -c`/`sh -c` wrapper could walk straight past [New capability]
The guard that's supposed to stop an agent from running `rm`/`rmdir` on a critical path (filesystem root, a direct child like `/usr` or `/etc`, your home directory, or the working directory and its parents) only caught the command when it appeared directly — wrapping the same `rm -rf` inside a `bash -c "..."` or `sh -c "..."` script let it slip through unprompted in `bypassPermissions` mode or under a shell allow rule. Reported against 2.1.280 on Sept 23, fixed in 2.1.288, which reached npm Oct 2 18:30 UTC. Confirmed via the official GitHub changelog (high confidence on the fix existing) plus secondary write-ups (mixed-news.com, windowsforum.com) for the exploit description, medium-high confidence on those details.
One actionable wrinkle: the `stable` npm tag reportedly still points at 2.1.285 as of this fix, so pinning `stable` wouldn't have this patch yet — worth checking `claude --version` / update channel directly rather than assuming "latest stable" means "patched," especially before running anything in `bypassPermissions`/auto mode (which Brian already uses) against a real filesystem.
