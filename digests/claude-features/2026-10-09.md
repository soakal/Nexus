# Claude + AI Digest — 2026-10-09

## 1. Claude Code 2.1.295 ships — hooks get a fail-closed mode, two real permission-scope bypasses fixed, `stable` now 9 releases behind `latest` [New capability]
Confirmed from the official `CHANGELOG.md` on GitHub (high confidence). New: `onFailure: "block"` for command/HTTP hooks — a hook that can't start, times out, or exits with an unexpected code now blocks the action instead of silently letting it through (previously a crashed guard hook == no guard). Fixed: `--tools`/`--restricted` weren't applying to built-in tools that registered after launch, and deprecated tool names could still reach tools outside the caller's restricted set — both are real permission-scope bypasses, not cosmetic. Also fixed: Bash permission checks for for-loops over glob patterns, and a mod's guard hook being handed a truncated nested tool input with no error (so a guard could "approve" content it never actually saw). Checked npm dist-tags directly: `stable` moved to 2.1.286, `latest`/`next` both sit at 2.1.295 — a 9-version gap, one wider than yesterday's 8.
Tie-in: any instruction-style or pattern-match `PreToolUse`/hook guard Brian runs — including Council Loop's `/loop` config and the ponytail-mode skill's own guard hooks — was exposed to the "hook crashes, action proceeds" failure mode `onFailure: "block"` now closes; worth checking whether those configs opt into the new setting, and whether they're pinned to `stable` (2.1.286, missing this entirely) or `latest`.

## 2. MCP gets a reliability pass, and Claude.ai connectors now default to the 2026-07-28 "stateless" protocol revision [New capability]
Still from `CHANGELOG.md`, same 2.1.295 release (high confidence). Changed: claude.ai-managed MCP connectors now negotiate protocol version `2026-07-28` by default on fresh installs (`MCP_PROTOCOL_NEGOTIATION=legacy` opts back out) — this is the same major spec revision Oct 7's digest flagged Claude Code itself needing a stdio-negotiation fix for. Fixed in the same release: remote MCP reconnects now back off (up to 30s) instead of tight-looping after an outage over 15s or a server that drops the connection right after accepting it; a server that repeats a pagination cursor is no longer asked for the same page up to 20 times per connect; non-text files an MCP tool returns (CSS/JS/XML, fonts/icons) get their real extension instead of being forced to `.bin` (which the Read tool refuses); MCP tool descriptions loaded via tool search are now cut at 16,384 characters instead of 2,048; WebSocket MCP servers get the same 16 MiB message cap the other transports already enforced.
Tie-in: NEXUS's `requirements.txt` pins `mcp==1.9.4` specifically because a prior `mcp` bump pulled a `starlette` release that broke FastAPI's `<0.39.0` pin — worth a quick check of whether `mcp==1.9.4` cleanly speaks protocol `2026-07-28` now that Claude Code's own connectors default to it, and the pagination-cursor fix is worth knowing about if MCP_Obsidian's vault-search tools ever return paginated results.
