# Claude + AI Digest — 2026-10-08

## 1. Claude Haiku 5.5 ships as the new default Haiku on the API — roughly 10x cheaper than 4.5 [New capability]
Confirmed straight from the official `CHANGELOG.md` on GitHub (high confidence): Claude Code 2.1.293 (published Oct 7) added `claude-haiku-5-5`, now the default Haiku model on the Anthropic API — 1M context window, $0.10/$0.50 per Mtok input/output ($0.50/$2.50 for prompts over 100K). That's roughly a 10x price cut and a big context jump versus Haiku 4.5.
Tie-in: NEXUS's `backend/agents/router.py` hardcodes `HAIKU_MODEL = "claude-haiku-4-5-20251001"` and prices it at $1.00/$5.00 per Mtok in `_PRICE_PER_MTOK` — the exact model Haiku handles chat intent routing/classification and the facts/goal extractors. Swapping that one constant to `claude-haiku-5-5` (and updating the price-table entry so the cost governor's spend caps stay accurate) would cut the cost of every Haiku-routed call roughly 10x, with more headroom for long tool-result context in `run_with_tools`.

## 2. A prompt-hook phrasing bypass got fixed, and the `stable` channel now sits 8 releases behind `latest` [New capability]
Still from `CHANGELOG.md` (high confidence): 2.1.294 (published today, currently only on the npm `next` tag, not yet promoted to `latest`) fixed `prompt`/`agent` hooks written as plain-English instructions (e.g. "Block commands that...") actually allowing what they were meant to block, plus made Stop/SubagentStop instruction-style hooks ("Carry on if the build is broken") judged more reliably so Claude stops early less often. Separately, 2.1.293 fixed an HTTP MCP connection memory leak (it retained every request sent until the connection closed). Checked npm dist-tags directly: `stable` is still pinned at 2.1.285, `latest` is 2.1.293, and `next` is 2.1.294 — an 8-version gap between stable and latest, one wider than yesterday's seven.
Tie-in: anyone relying on an instruction-style (not pattern-match) `PreToolUse`/`Stop` hook — including a custom guard in Council Loop's `/loop` config — was exposed to the exact phrasing-bypass class this patch closes, and it isn't in `stable` yet. NEXUS's `mcp` pin (`1.9.4`, already noted as fragile against upstream `starlette` breaks) doesn't touch this leak directly since it's CLI-side, but it's one more reason to track whether a future `mcp` bump interacts with Claude Code's own MCP client changes rather than assuming they're independent.
